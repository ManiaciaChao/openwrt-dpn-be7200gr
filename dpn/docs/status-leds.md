# 状态 LED

仅启用已经逐灯确认的四路 active-low 指示灯。Power GPIO17 与其余无标签位置尚未
对应，不注册它们；也不操作原厂设备树中的 PHY 控制信号。

| 灯 | GPIO | 默认状态来源 |
| --- | --- | --- |
| NET | 20 | wan10 的链路及收发流量 |
| 2.4G | 15 | phy0.0-ap0 的链路及收发流量 |
| 5G | 13 | phy0.1-ap0 的链路及收发流量 |
| Mesh | 22 | 任一 AP 的 WPS PBC 窗口，500 ms 亮/500 ms 灭，结束或取消后熄灭 |

NET 使用内核 netdev 触发器，表示上联接口链路，不探测外网是否可达。无线灯也使用
netdev 触发器，无线关闭、接口删除后熄灭，接口恢复后重新跟随。
Mesh 灯不表示 802.11s/EasyMesh 已组网。WPS 默认仍关闭，启用配对后才显示窗口。

LuCI「系统 → LED 配置」可以改变关联接口及触发器；修改无线接口名称后也应调整
LED 的关联接口。初始化只添加缺失的 dpn_* 配置节，保留既有设置。
Mesh 改成其他触发器后，WPS 状态进程停止接管它。

新源码使用标准 gpio-leds 设备树节点和内置 GPIO LED 驱动；运行中的旧 RC3 内核没有
这些节点，因此本机安装了匹配内核的 gpio-leds 模块和四路 platform-data 回移模块。
服务设置为开机启动，并已验证从完全卸载模块的状态重新创建设备及触发器。
没有进行整机重启验收，没有重刷固件。旧固件上的回移文件位于 overlay，恢复默认设置
或刷回不含此功能的旧包会丢失补丁；新版源码将驱动和定义放入固件本身。

已验证：无线灯随两个频段关闭/恢复，WPS 开始时 Mesh 闪烁、取消后熄灭，原无线文件
逐字节恢复，用户确认机身显示一致。实际新 DT 已编译并核对仅含四路已确认 GPIO。
尚未重新构建、验收及发布包含此改动的两种完整固件；RC2 下载文件未替换。

## 管理密码与 SSH

root 密码用于 LuCI；SSH 允许密码认证时也使用同一个 root 密码，并无单独的 SSH
密码。当前本机保持公钥登录，PasswordAuth 和 RootPasswordAuth 都为 off。

用自己的密钥登录后执行 passwd，或者在 LuCI「系统 → 管理权」修改 root 密码。
电脑端也可执行下面的交互命令，将 ROUTER_IP 替换为管理地址：

```sh
ssh -t root@ROUTER_IP passwd
```

若需要密码 SSH，在 LuCI 的 SSH 访问设置中同时启用密码认证和 root 密码登录。
不向公共固件预置共用密码，也不在文档中发布本机密码或私钥。
